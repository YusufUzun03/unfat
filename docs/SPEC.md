# UnFat — Spec

Personal calorie/macro and workout tracker for iPhone, released on the App Store (Turkey storefront). Research behind every decision: `docs/research/` (`ios-stack.md`, `data-and-science.md`, `github-competitors.md`).

## Goals
- Log food in under 10 seconds for common cases (recents, barcode, photo draft).
- Run a gym session from a program with prefilled sets, auto rest timer and an interactive Lock Screen / Dynamic Island Live Activity.
- Show today's calories and macros at a glance: app, Home Screen widget, Lock Screen widget.
- Apple-quality UI: plain, flat, one accent color, fluid native animations, haptics.
- Zero running cost; no own backend.

## Non-goals (MVP)
Apple Watch app, Android, social/sharing, AI coach/chat, meal plans and recipes builder, micronutrients beyond fiber, subscriptions/paywall/ads, English localization (strings live in a String Catalog so it can be added later), iPad layout.

## Stack
- Swift 6, SwiftUI, **iOS 26.0 minimum**, iPhone only. Liquid Glass via the iOS 26 SDK defaults.
- Xcode 26.x on GitHub Actions `macos-26` runners (public repo, free). Project generated by **XcodeGen** (`ios/project.yml`); `.xcodeproj` is not committed.
- SwiftData + CloudKit private DB; WidgetKit + ActivityKit + App Intents; HealthKit; VisionKit `DataScannerViewController`; Swift Charts.
- SPM dependencies: `firebase-ios-sdk` (FirebaseAI + App Check only). Nothing else unless a task brief allows it.
- Bundle IDs: `io.github.yusufuzun03.unfat`, extension `io.github.yusufuzun03.unfat.widgets`. App Group `group.io.github.yusufuzun03.unfat`. iCloud container `iCloud.io.github.yusufuzun03.unfat`.

## Dev loop without a Mac
- **A — CI compile + tests**: every push builds for the simulator and runs unit tests (~3-5 min).
- **B — device IPA**: `workflow_dispatch target=device-ipa` → development-signed IPA artifact → install from Windows over USB with go-ios (fallback: TestFlight).
- **C — TestFlight**: `target=testflight`.
- **D — screenshots job**: CI boots an iPhone 17 Pro Max simulator, launches the app with `-UNFAT_SCREEN <name>` (debug-only launch argument that opens a screen with fixture data) and uploads PNGs. Used for orchestrator visual review and later for App Store screenshots.
- **E — debug gallery + tuning panel** (DEBUG builds): every component and the Live Activity/widget views rendered in-app; spring/duration values adjustable live on the phone.

## Data model (SwiftData)
CloudKit rules apply to synced types: every property optional or defaulted, no `.unique`, all relationships optional with inverses, schema changes additive only after first production deploy.

Two configurations in one container (store in the App Group):
- **Synced** (`.private(iCloud…)` when sync is on, `.none` when off): `UserProfile`, `CustomFood`, `FoodEntry`, `FavoriteFood`, `WeightEntry` (user-entered only), `Program`, `ProgramDay`, `PlannedExercise`, `WorkoutSession`, `SessionExercise`, `SetLog`, `CustomExercise`.
- **Local only** (`.none`): `CachedProduct` (OFF cache), `HealthDaySummary` (steps, active kcal, Health weights). HealthKit data never syncs (guideline 5.1.3(ii)).
- Seed foods and exercises are **read-only bundled JSON** loaded into memory and indexed for search; not stored in SwiftData.

Key rules:
- `FoodEntry` stores a **snapshot** (name, kcal/protein/carb/fat/fiber per 100 g, grams, serving label, source, `foodRef` string like `seed:123` / `off:869…` / `custom:<uuid>`), never a relationship to a food. History never changes when a food is edited, and no cross-configuration relationships exist.
- No meal buckets: entries are a timestamped timeline (optional free-text tag).
- `SetLog`: reps, weightKg, isDone, completedAt, optional RPE. Previous values for prefill come from the last session containing the same exercise.
- Widget data: the app writes `WidgetSnapshot` JSON (date, kcal eaten/target, P/C/F eaten/target) to the App Group after every change and calls `WidgetCenter.reloadAllTimelines()`. Widgets never open the database.

## Nutrition and training logic (UnFatCore)
Formulas and constants as in `data-and-science.md` §3:
- BMR Mifflin-St Jeor; TDEE = BMR × activity factor; goal rate capped at 1 % body weight/week.
- Defaults: protein 1.8 g/kg (range 1.6-2.2), fat 27 % kcal, carbs = remainder. All editable.
- Floors: warning below 1,200 kcal (female) / 1,500 kcal (male); never blocks.
- Adaptive TDEE after ≥14 days with ≥10 weigh-ins and ≥10 logged days: EMA trend weight (α = 0.1), TDEE = mean intake − Δtrend × 7,700 / days, blended with the previous estimate and clamped ±15 %/week. Suggests new targets; user accepts.
- Workout kcal: (MET − 1) × 3.5 × kg / 200 × minutes, strength MET from exercise data.
- e1RM: Epley (reps ≤ 10 shown), PR detection per exercise.

## External integrations
| Integration | Use | Notes |
|---|---|---|
| Open Food Facts API v3 | barcode lookup | one call per scan, cache locally, custom `User-Agent: UnFat/<ver> (github URL)`, ODbL attribution in About; missing product → custom food form prefilled with barcode |
| Gemini Flash-Lite via Firebase AI Logic + App Check (App Attest) | photo → editable draft | free Spark plan, Turkey storefront only (EEA/UK excluded by free tier), 18+ age rating note, explicit consent screen before first photo; `GoogleService-Info.plist` injected from a CI secret, not committed |
| HealthKit | read body mass, steps, active energy; write `HKWorkout` (traditional strength training) with energy | local-only cache, usage strings, privacy policy page |
| CloudKit | opt-in sync | schema deployed to Production before TestFlight sync tests |

Photo flow returns structured JSON (items: name, grams, kcal, P/C/F, confidence) shown as editable rows with a question about oil/sauce; nothing is logged until the user confirms.

## Key flows
1. **Onboarding** (once): sex, birth year, height, weight, activity, goal (lose/maintain/gain + rate) → computed targets, editable → optional Health and notification permissions.
2. **Log food**: global add (iOS 26 tab bar search-role tab "Ekle") → recents/favorites on top, search across custom + seed + cached OFF → entry editor with custom keypad, serving chips, live kcal/macro preview → save (ring animates, light haptic). Alternatives from the same sheet: barcode, photo, quick kcal, copy yesterday.
3. **Workout**: pick program day (or empty session) → exercises with sets prefilled from last time → tap check → rest timer starts in app + Live Activity (countdown, ±15 s, skip, complete next set) + local notification at rest end → finish → summary (duration, volume, kcal, PRs) → write HKWorkout.
4. **Progress**: weight entry, trend line, weekly average intake vs target, adaptive TDEE card, per-exercise e1RM chart.

## Design
Apple style: flat, plain backgrounds, grouped lists over card stacks, no gradients, no emoji, one accent color, SF Pro + SF Rounded for numbers, `contentTransition(.numericText())` for changing numbers, spring animations, `sensoryFeedback` haptics. Overshooting the target is never red (neutral tone). Concrete tokens and screen mockups: section "Design decisions" below (filled after mockup review).

### Design decisions
Approved 2026-11-03 (mockups: Today, entry editor, active workout, Lock Screen Live Activity).
- **Color**: one accent `#FF6A3D` (coral orange) in light and dark (`AccentColor` asset). Everything else uses system semantic colors: `systemGroupedBackground`, `secondarySystemGroupedBackground`, `label`, `secondaryLabel`, `tertiaryLabel`, `separator`. Bar/ring tracks use `tertiarySystemFill`. No other hues except system red for destructive actions only.
- **Over target**: ring completes in accent; the overflow continues as a second lap in `secondaryLabel`; text says "120 kcal fazla" in `secondaryLabel`. Never red.
- **Type**: SF Pro for text, SF Rounded (`.fontDesign(.rounded)`) for all numbers, `monospacedDigit()` on timers. Large title for tab roots; hero numbers 34 pt semibold rounded.
- **Spacing**: 4 / 8 / 12 / 16 / 24 / 32 scale; screen side margin 16; grouped container corner radius 14 (continuous); chips are capsules.
- **Layout**: grouped lists and plain sections, not card stacks. Entry timeline rows: time (secondary, monospaced) · name · kcal right-aligned.
- **Components**: calorie ring (stroke 11 pt on a 110 pt ring, round caps, value + "kcal kaldı" centered); macro bars (5 pt, capsule, accent fill); entry editor with summary block (kcal + P/K/Y), serving chips (selected = accent fill, white text), custom 3×4 keypad, full-width accent "Ekle" button; set rows (Set · kg · Reps · check circle, done = accent); rest block (time, −15 / +15 / Geç, progress bar).
- **Motion**: default `.spring(duration: 0.35, bounce: 0.15)`; ring fill `.spring(duration: 0.6, bounce: 0.1)`; numbers `.contentTransition(.numericText())`; sheet and navigation use system transitions; respect Reduce Motion (fades instead of springs). All values live in `Motion` tokens and are tunable in the DEBUG panel.
- **Haptics**: `.success` on food logged, `.impact(.light)` on set check, `.warning` never used for targets.
- **Tabs**: Bugün (`sun.max`), Antrenman (`dumbbell`), İlerleme (`chart.line.uptrend.xyaxis`), Ekle (`plus`, `Tab(role: .search)` so it sits apart in the iOS 26 tab bar and opens the add sheet).
- **Live Activity**: Lock Screen banner = workout · exercise, "Set x / y", rest countdown in accent (`Text(timerInterval:)`), progress bar, three buttons (+15 sn, Geç, Set tamam — the last one accent). Dynamic Island compact: dumbbell icon leading, countdown trailing in accent; minimal: countdown; expanded: exercise + set leading, countdown trailing, "Set tamam" bottom.
- **Widgets**: small = ring + kcal left; medium = ring + three macro bars; `accessoryCircular` = `Gauge` with kcal left.

## App Store requirements (MVP release)
Disclaimer + methodology page (1.4.1), privacy policy (GitHub Pages), HealthKit usage strings and no HealthKit data in iCloud (5.1.3), AI photo consent (5.1.2(i)), `PrivacyInfo.xcprivacy`, ODbL + library acknowledgements screen, screenshots from loop D, Turkey storefront only, age rating 18+ only if the Gemini terms require it at submission time.

## Definition of done (MVP)
- All flows above work on the real iPhone from a TestFlight build.
- Live Activity shows and counts down on the Lock Screen and Dynamic Island; its buttons work with the app suspended.
- Widgets update within seconds of logging.
- Sync on: data appears on a second device or after reinstall; sync off: app fully works.
- CI green: build, unit tests (UnFatCore coverage of all formulas), entitlement check, screenshots job.
- App Store submission package complete (metadata, screenshots, privacy answers).
