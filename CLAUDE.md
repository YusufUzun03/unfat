# UnFat

Native iOS 26 calorie + workout tracker. Swift 6 / SwiftUI / SwiftData+CloudKit / WidgetKit+ActivityKit / HealthKit. Spec: `docs/SPEC.md`, tasks: `docs/PLAN.md`, file index: `filemap.md`, research: `docs/research/`.

## No Mac
- There is no local Xcode. Every build runs on GitHub Actions (`.github/workflows/ios.yml`, `macos-26`).
- Compile + tests: push, or `gh workflow run ios.yml -f target=compile`. Watch: `gh run watch`.
- Screenshots for review: `gh workflow run ios.yml -f target=screenshots`, then `gh run download <id>`.
- Device build: `target=device-ipa` (install with go-ios) or `target=testflight`.
- `UnFatCore` (pure Swift package) may also build locally with Swift for Windows if installed; not required.
- The `.xcodeproj` is generated by XcodeGen from `ios/project.yml` and never committed. Add files by path, not by editing a project file.

## Conventions
- Code, comments and identifiers in English; user-facing strings in Turkish via `Localizable.xcstrings`, never hardcoded.
- SwiftData synced models follow CloudKit rules: optional or defaulted properties, no `.unique`, optional relationships with inverses, additive changes only.
- `FoodEntry` stores a nutrition snapshot, never a relationship to a food.
- HealthKit data lives only in the local-only configuration; it must never sync.
- Widgets and the Live Activity read the App Group `WidgetSnapshot` / activity state, never the database.
- Formulas live in `UnFatCore` with tests; views do no nutrition math.
- Design: tokens in `DesignSystem/`, one accent color, no gradients, no red for "over target". New screens need a `-UNFAT_SCREEN` route with fixture data.
- Never commit `GoogleService-Info.plist`, `*.p8`, `*.mobileprovision`; CI injects them from secrets.
- Do not copy code from GPL/AGPL/unlicensed repos listed in `docs/research/github-competitors.md`.
- Update `filemap.md` when adding or moving files.
